Detailed Description

DCC CV memory space (0xF8) with deferred replies.

See openlcb_application_dcc_cv.h for the contract. This file holds the small table of requests that are waiting for the application, the request handlers that fill it, and the run function that sends the replies.

A request goes through these states:

FREE –request, hook says PENDING--> WAITING –complete() or timeout--> REPLY –sent--> FREE

A request the hook answers at once never enters the table for longer than the hook call.

void OpenLcbApplicationDccCv_handle_read_request ( openlcb_statemachine_info_t * statemachine_info,
config_mem_read_request_info_t * config_mem_read_request_info )

Read request function for space 0xF8.

Read request function for space 0xF8 (wired as read_request_dcc_cv).

Algorithm:

  1. Reject anything but a one-byte read
  2. Absorb a request identical to one already outstanding
  3. Take a slot (none free: temporary error, the requester will retry)
  4. Call the application hook
  5. PENDING: keep the slot and send no reply now. Otherwise free the slot and load the reply.

◆ OpenLcbApplicationDccCv_run()

void OpenLcbApplicationDccCv_run ( uint8_t current_tick)

Sends finished replies and times out requests the application never completed.

Algorithm, per slot:

  1. WAITING for longer than USER_DEFINED_DCC_CV_TIMEOUT_TICKS: result becomes ERROR_TEMPORARY_TIME_OUT and the slot moves to REPLY
  2. REPLY: try to send; free the slot once sent, or once it has been stuck for longer than the timeout (the bus is not taking traffic and the requester has given up by now)
* @param current_tick  Global 100 ms tick.
*
